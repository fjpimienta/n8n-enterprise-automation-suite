## 🛡️ Critical Risk Management (Guardrails)
- **Zero-Config Rigidity (Stateless Enforcement):** Absolute restriction. The library must NEVER store, import, or hardcode environment variables, backend URLs, or strict branding styles. All configuration values must be injected dynamically from the host application via Dependency Injection tokens.
- **Session Lifecycle Stability:** Ensure internal `sessionId` management relies on clean UUID v4 generation and proper persistence mechanisms to prevent conversational context loss inside the n8n orchestrator memory windows.
  - **Known deviation (#1038):** The ID is `'web-' + crypto.randomUUID()` ([ai.service.ts:24](src/lib/services/ai.service.ts#L24)): a UUID v4 with a `web-` prefix, generated once per `AiService` instance. It is not persisted (no `localStorage`/`sessionStorage` in `src/lib`), so a new service instance starts a new conversation.
- **Optimistic UI Consistency:** Maintain the optimistic update pattern. When a user triggers a message, render the input immediately along with a typing loader ("...") on the message stack before executing the HTTP transport client.

## 💻 Tech Stack & Architectural Constraints
- **Core Framework:** Angular (v18+ / v21) enforcing decoupled, standalone architectures (No NgModules allowed).
- **Design Pattern:** Strict Smart Service / Dumb Component architecture. The visual presentation layout (`AiChatComponent`) must remain stateless and UI-focused, delegating session token handling and Webhook streaming entirely to `ChatService` / `AiService`.
  - **Known deviation (#1038):** There is no `ChatService`; the only service is `AiService` ([ai.service.ts:19](src/lib/services/ai.service.ts#L19)). There is no webhook streaming: each message is one `http.post` that resolves with the complete `output` ([ai.service.ts:46-59](src/lib/services/ai.service.ts#L46), [:87-93](src/lib/services/ai.service.ts#L87)). `AiChatComponent` also holds draft and file state (`userInput`, `selectedFile`, `previewUrl`, `attachmentError`: [ai-chat.component.ts:20](src/lib/components/ai-chat/ai-chat.component.ts#L20), [:27-29](src/lib/components/ai-chat/ai-chat.component.ts#L27)) and creates object URLs ([ai-chat.component.ts:113](src/lib/components/ai-chat/ai-chat.component.ts#L113)).
- **State Management:** Reactive rendering powered exclusively by Angular Signals to handle message stack updates without causing unnecessary Zone.js overhead.
  - **Known deviation (#1038):** Not signals-only. `userInput` ([ai-chat.component.ts:20](src/lib/components/ai-chat/ai-chat.component.ts#L20)) and `destroyed` ([:30](src/lib/components/ai-chat/ai-chat.component.ts#L30)) are plain fields; the draft is bound with `[(ngModel)]` ([ai-chat.component.html:69](src/lib/components/ai-chat/ai-chat.component.html#L69)).
- **Communication Layer:** HTTP Client executing POST requests against configured n8n automation suite gateways.
  - **Known deviation (#1038):** No tenant check before sending. `tenant_id` is read from `this.tenantService.activeTenant()?.id_company` ([ai.service.ts:44](src/lib/services/ai.service.ts#L44), [:84](src/lib/services/ai.service.ts#L84)) and put in the body ([:46-49](src/lib/services/ai.service.ts#L46), [:87-91](src/lib/services/ai.service.ts#L87)). The only guards are for `query` and `apiUrl_ai` ([:38](src/lib/services/ai.service.ts#L38)) and `attachments.enabled` ([:65](src/lib/services/ai.service.ts#L65)). If `activeTenant()` is null, `tenant_id` is dropped by JSON serialization and the request is still sent. The suite-wide fail-closed rule (root `CLAUDE.md`, section 2) requires refusing to send. Verified in `core-auth`: `TenantService.activeTenant()` can return `null`; it is a `signal<TenantContext | null>` initialized from storage (`core-auth/src/lib/services/tenant.service.ts:14`) and `clearContext()` sets it to `null` (`:62`).

## 📝 Component API & Layout Checklist
- **Token Configuration Binding:** External app parameters must strictly map into the library using `CHAT_CONFIG_TOKEN` providing `apiUrl_ai`, `title`, `logoUrl`, and `primaryColor`.
  - **Known deviation (#1038):** `primaryColor` is declared in the token type ([chat-config.ts:14](src/lib/interfaces/chat-config.ts#L14)) but nothing in `src/lib` reads it. The stylesheet uses `var(--primary-color, #206bc4)` ([ai-chat.component.css:171](src/lib/components/ai-chat/ai-chat.component.css#L171)), and no code in `src/lib` sets that variable, so the library ignores the configured color.
- **Optional attachments:** `attachments` (`ChatAttachmentsConfig`: `enabled`, `maxSizeMb`, `accept`) in `CHAT_CONFIG_TOKEN`, declared in [chat-config.ts](src/lib/interfaces/chat-config.ts). Off by default; one file per message; size capped at 5 MB; the file is sent as `file: { name, type, size, base64 }` in the same POST only when attached. Details and the request contract are in the README, "Optional File Attachments".
- **Documented but not implemented (#1038):** the full list (inputs, outputs, markdown, `ChatService`, streaming, persistence, tenant guard) is in the README, section "Documented but not implemented (#1038)". This file keeps the rules as written.
- **Public Component Interface (`<lib-ai-chat>`):**
  - **Inputs:** `[sessionId]` (`string`, defaults to a new `uuid()`), `[isOpen]` (`boolean`, defaults to `false`).
    - **Known deviation (#1038):** Neither input exists. `AiChatComponent` declares no `input()` or `@Input()` ([ai-chat.component.ts:15](src/lib/components/ai-chat/ai-chat.component.ts#L15)). `isOpen` is an internal `signal(false)` ([ai-chat.component.ts:19](src/lib/components/ai-chat/ai-chat.component.ts#L19)), and `sessionId` is a private field of `AiService` ([ai.service.ts:24](src/lib/services/ai.service.ts#L24)). The default `false` holds, but hosts cannot set either value.
  - **Outputs:** `(onMessageSent)` (emits raw `string`), `(onClose)` (emits `void` on widget minimization).
    - **Known deviation (#1038):** Neither output exists. There is no `output()`, `@Output()` or `EventEmitter` in `src/lib`, so `onMessageSent` and `onClose` are never emitted. The toggle only flips the internal signal via `toggleChat()` ([ai-chat.component.ts:41-43](src/lib/components/ai-chat/ai-chat.component.ts#L41), [ai-chat.component.html:1](src/lib/components/ai-chat/ai-chat.component.html#L1)).
- **UI UX Requirements:** Implement mandatory auto-scroll behaviors upon new incoming array updates, "Enter" key press triggers, distinct chat bubble styles to differentiate user vs assistant, and native markdown parsing support (handling bold structures and lists).
  - **Known deviation (#1038):** Markdown is not rendered. Messages are interpolated as plain text ([ai-chat.component.html:25](src/lib/components/ai-chat/ai-chat.component.html#L25), `{{ msg.text }}`), so `**bold**` and list markers show literally. `src/lib` has no markdown parser, `innerHTML` or `DomSanitizer`. The only sanitizer is for file names ([attachment.util.ts:48](src/lib/utils/attachment.util.ts#L48)), not for text.
